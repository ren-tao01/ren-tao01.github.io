Transformers

Stack attention, add positions, sprinkle in residual connections and a feed-forward layer. That's the recipe behind every modern large language model.

The whole architecture, in one breath

A Transformer is a stack of identical blocks. Each block has two sub-layers: a multi-head self-attention layer and a small feed-forward network. Both sub-layers are wrapped in residual connections and layer normalization. Inputs are token embeddings plus positional encodings. Outputs are vectors — one per input position — that you read off either to predict the next token (decoder-only / GPT style) or to feed a downstream task (encoder, BERT style).

The original 2017 paper bundles an encoder (for the source sentence) and a decoder (for the target sentence) wired by cross-attention. Modern LLMs almost always drop the encoder and use a decoder-only stack. We'll build both pictures here.

Why it works

Every layer mixes information across positions (attention) and then refines each position independently (FFN). Stack a dozen of these and you get arbitrarily deep, position-aware representations — without ever passing a hidden state sequentially through time.

Positional encoding — fixing attention's blind spot

Self-attention is permutation-equivariant: shuffle the input tokens and the outputs shuffle the same way. That is a bug, not a feature, for language. "Dog bites man" and "Man bites dog" must produce different representations.

The fix: before the first block, add a position-dependent vector $\mathbf{p}_i$ to each token embedding $\mathbf{x}_i$:

$$ \mathbf{z}_i \;=\; \mathbf{x}_i + \mathbf{p}_i. $$

The original sinusoidal encoding sets, for position $i$ and embedding dimension index $2k$ or $2k+1$:

$$ \mathbf{p}_{i, 2k} = \sin\!\left( \frac{i}{10000^{2k/d}} \right), \qquad \mathbf{p}_{i, 2k+1} = \cos\!\left( \frac{i}{10000^{2k/d}} \right). $$

Each dimension is a sinusoid; different dimensions oscillate at exponentially different rates, from very fast to very slow. The reason this particular form is convenient: any position offset $\Delta$ can be written as a linear transformation of the encoding at position $i$ (it's the angle-addition formula in disguise). So relative positions are recoverable by the attention mechanism even though we only injected absolute ones.

Most modern models use learned positional embeddings (just another lookup table indexed by position) or rotary position embeddings (RoPE) which rotate query and key vectors by an angle that depends on their position. The principle is the same: bake position into the input so attention can see it.

The Transformer block

Let $\mathbf{H} \in \mathbb{R}^{n \times d}$ be the matrix of token vectors entering a block ($n$ tokens, $d$ features each). The block computes:

$$ \mathbf{H}' \;=\; \mathbf{H} + \mathrm{MHA}\!\left( \mathrm{LN}(\mathbf{H}) \right), $$ $$ \mathbf{H}'' \;=\; \mathbf{H}' + \mathrm{FFN}\!\left( \mathrm{LN}(\mathbf{H}') \right). $$

Two residual connections, two LayerNorms, one MHA, one FFN. That's the entire block.

Two stylistic notes worth knowing:

  • Pre-norm vs. post-norm. The original paper applied LayerNorm after each sub-layer (post-norm). Modern stacks almost always apply it before (pre-norm), as drawn above. Pre-norm trains more stably at depth.
  • Residuals are everywhere. Without them, gradients through a 24-layer Transformer would never reach the bottom embedding table. With them, every block has a direct gradient path back to the input. Same trick we used in ResNet (Ch 11).

The position-wise feed-forward network

After attention has mixed information across positions, the FFN refines each position independently. It is a tiny two-layer MLP applied to every token vector with shared weights:

$$ \mathrm{FFN}(\mathbf{h}) \;=\; \mathbf{W}_2\, \phi(\mathbf{W}_1 \mathbf{h} + \mathbf{b}_1) + \mathbf{b}_2. $$

The hidden width is conventionally $4d$ — so an FFN with $d = 1024$ has a 4096-unit hidden layer. The activation $\phi$ is GELU in modern models (a smooth ReLU variant), or sometimes SwiGLU.

Why "position-wise"? Because the same $\mathbf{W}_1, \mathbf{W}_2$ are applied to every row of $\mathbf{H}$. The FFN never looks at neighbours; that job is exclusively attention's. The split — attention mixes across positions, FFN refines each position — is the cleanest way to read the architecture.

One often-overlooked fact: the FFN holds most of the parameters in a Transformer. With $d = 1024$, attention has $\sim 4 d^2 = 4{,}194{,}304$ parameters per block (four projection matrices) but the FFN has $\sim 8 d^2 = 8{,}388{,}608$ (two $d \times 4d$ matrices). Scaling laws care about the FFN.

Layer normalization, briefly

We saw batch normalization in Chapter 10. LayerNorm is its sequence-friendly cousin. Where BatchNorm normalizes each feature across the batch, LayerNorm normalizes each token vector across its features. For a vector $\mathbf{h} \in \mathbb{R}^d$:

$$ \mu = \frac{1}{d} \sum_{j=1}^d h_j, \quad \sigma^2 = \frac{1}{d} \sum_{j=1}^d (h_j - \mu)^2, $$ $$ \mathrm{LN}(\mathbf{h}) = \boldsymbol{\gamma} \odot \frac{\mathbf{h} - \mu}{\sqrt{\sigma^2 + \varepsilon}} + \boldsymbol{\beta}. $$

$\boldsymbol{\gamma}, \boldsymbol{\beta} \in \mathbb{R}^d$ are learned scale and shift. Because the mean and variance are computed per token, LayerNorm doesn't depend on batch size, doesn't need a running average, and works exactly the same at training and inference time. That makes it ideal for variable-length sequences and autoregressive generation.

Encoder, decoder, decoder-only

Stacking $N$ blocks gives you a tower. There are three flavours of tower in common use:

Encoder (BERT-style)

$N$ blocks, all using unmasked self-attention. Every position attends to every other position, in both directions. Useful when you have the whole input up front and want representations of it (classification, search, sentiment).

Decoder-only (GPT-style)

$N$ blocks, all using causal self-attention (the triangular mask from Ch 13). Position $t$ can only attend to positions $\le t$. Train it to predict the next token; at inference, sample one token at a time. This is the architecture behind essentially every modern LLM.

Encoder–decoder (translation, T5)

An encoder reads the source sentence; a decoder generates the target sentence. Each decoder block has a third sub-layer: cross-attention, where the queries come from the decoder's previous layer but the keys and values come from the encoder's output. The decoder is causal among its own tokens but free to look anywhere in the source.

Cross-attention is just the same attention formula with a different wiring: $\mathbf{Q}$ from decoder, $\mathbf{K}, \mathbf{V}$ from encoder. Three matrices in, one matrix out.

The full decoder-only stack, end to end

Let's trace what happens to a sequence of tokens "the cat sat" in a decoder-only Transformer with $N$ blocks, vocabulary size $V$, embedding dimension $d$, and context length $T$.

  1. Tokenize. Split the string into integer ids using a tokenizer (BPE, SentencePiece). "the cat sat" → $[ 50, 712, 904 ]$. Sequence length $n = 3$.
  2. Embed. Look up each id in an embedding matrix $\mathbf{E} \in \mathbb{R}^{V \times d}$, giving an $n \times d$ matrix of token embeddings.
  3. Add positions. Add positional encoding $\mathbf{P}$ (or apply RoPE inside attention). Result: $\mathbf{H}_0 \in \mathbb{R}^{n \times d}$.
  4. Run $N$ blocks. $\mathbf{H}_\ell = \mathrm{Block}(\mathbf{H}_{\ell-1})$ for $\ell = 1, \ldots, N$. Each block applies pre-norm, masked MHA, residual, pre-norm, FFN, residual.
  5. Final LayerNorm. Apply one more LayerNorm to $\mathbf{H}_N$ to get well-scaled output vectors.
  6. Project to vocabulary. Multiply by an unembedding matrix $\mathbf{W}_U \in \mathbb{R}^{d \times V}$ — often weight-tied to $\mathbf{E}^\top$ — yielding logits $\mathbf{L} \in \mathbb{R}^{n \times V}$.
  7. Loss. At training, compute cross-entropy between row $i$ of $\mathbf{L}$ and the true token at position $i+1$. Sum over positions, average over the batch.
  8. Generate. At inference, take the last row $\mathbf{L}_n$, softmax it, sample a token, append it to the sequence, and repeat.
The training trick everything depends on

Because attention is causal, you can compute the loss for every position in the sequence in a single forward pass. One training example of length $T$ produces $T$ next-token-prediction losses. This is why pretraining is so dramatically efficient: every token in your corpus is a training signal.

Counting parameters

A useful sanity check before you train anything. For one decoder-only block with hidden size $d$ and FFN width $4d$:

  • Attention projections $\mathbf{W}_Q, \mathbf{W}_K, \mathbf{W}_V, \mathbf{W}_O$: $4 \times d \times d = 4d^2$ params.
  • FFN: $\mathbf{W}_1$ is $d \times 4d$, $\mathbf{W}_2$ is $4d \times d$, total $8d^2$ params.
  • Two LayerNorms: $4d$ params (negligible).

So one block is roughly $12 d^2$ parameters. With $N$ blocks, the body has $\approx 12 N d^2$ parameters. Add embeddings ($V d$) and you're done.

Plug in GPT-2 small ($d=768$, $N=12$): $12 \cdot 12 \cdot 768^2 \approx 85$M params for the body, $\approx 39$M for embeddings → $\approx 124$M total. Matches reality.

Plug in GPT-3 ($d=12288$, $N=96$): $12 \cdot 96 \cdot 12288^2 \approx 174$ billion params for the body. Embeddings (vocab $\approx 50{,}000$ tokens, no weight tying) add another $\sim 1.2$B, landing on the 175B headline figure. The whole thing is one back-of-the-envelope formula.

Why Transformers scale

Transformers replaced RNNs because they train better, not because they "compute more." Three properties matter:

  1. Parallelism along the sequence. An RNN must process tokens one at a time — the hidden state at step $t$ depends on step $t-1$. A Transformer block computes attention and FFN for all positions at once, as matrix multiplies. On a GPU, this is the difference between sequential and saturating the entire chip.
  2. Constant path length. Information from any position can reach any other position in one attention step, regardless of distance. RNN gradients have to traverse $\Delta t$ layers to connect positions $\Delta t$ apart, which causes vanishing. Transformers don't.
  3. Smooth scaling laws. Empirically, loss decreases as a smooth power law in model size, dataset size, and compute (Kaplan et al. 2020, Chinchilla 2022). You can predict from a small experiment what a 100× larger model will achieve. That predictability is rare in machine learning, and it's what made the LLM bet rational.

The price you pay is the $O(n^2 d)$ cost of attention — fine for sequences of a few thousand tokens, painful at a million. Most current research on architecture is about smarter attention (sliding window, sparse, linearized, state-space) that keeps the strengths above while taming the quadratic.

From Transformer to LLM

The leap from "the architecture in this chapter" to "the chatbot you talked to today" is mostly engineering and data, not new math. Three stages:

  1. Pretraining. Take a decoder-only Transformer with billions of parameters. Train on a trillion-token internet corpus to predict the next token. This single objective produces a model with surprising emergent capabilities: arithmetic, translation, reasoning, code.
  2. Supervised fine-tuning (SFT). Continue training on a curated dataset of (prompt, ideal response) pairs. The base model still does next-token prediction; we just point it at conversation-shaped data so its default style becomes "helpful assistant."
  3. Preference optimization (RLHF, DPO). Show the model two candidate responses for a prompt and a human label saying which is better. Use that signal to nudge the model toward responses humans prefer. This is what turns a fluent text completer into something that reliably follows instructions and refuses harmful requests.

Every one of those stages uses the gradient descent and backpropagation you learned in Chapters 7–10, the architecture you just built, and the cross-entropy loss from Chapter 5. Nothing new.

What you have learned

Pause for a moment. Fourteen chapters ago you started with the definition of a function and the slope of a line. You can now describe — with equations and from first principles:

  • Why a single neuron is a dot product through a non-linearity.
  • Why stacking neurons requires non-linearity to be expressive at all.
  • How a network learns: a loss surface, a gradient, a small step downhill, repeated billions of times.
  • How backpropagation makes that gradient cheap to compute, no matter how deep the network.
  • Why convolutions exploit spatial structure and why recurrence struggles with long-range dependence.
  • How attention sidesteps recurrence by reading every position in parallel through a learned similarity.
  • How a Transformer is just a residual stack of attention and feed-forward layers, and why that recipe scales.

Every modern AI system you read about — language models, image generators, code assistants, protein folders — is built from these same parts, sometimes rearranged, never fundamentally different. The frontier is huge, but the foundations are not. You have them.

Self-check

  1. Why does self-attention need positional encoding at all?
  2. What is the difference between pre-norm and post-norm, and which is more stable?
  3. Where do most of a Transformer's parameters live — attention or FFN?
  4. What is the one architectural difference between a decoder-only Transformer and an encoder-only Transformer?
  5. Why does causal masking let you compute $T$ next-token losses in one forward pass?

Answers: because attention is permutation-equivariant; without positions, the model cannot distinguish word order. Pre-norm puts LayerNorm inside the residual branch, before each sub-layer; it trains more stably at depth, especially past 12 layers. The FFN — roughly $8d^2$ vs. $4d^2$ for attention. The mask in self-attention: encoder-only is unmasked (bidirectional); decoder-only is causal (triangular). Because each output position depends only on positions to its left, position $t$ can predict token $t+1$ without leaking it; running through the sequence once produces $T$ independent training signals.
